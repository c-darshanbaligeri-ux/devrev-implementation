Knowledge Configuration & Curation Guide

This guide covers how to select, configure, and curate knowledge sources for DevRev agents so they retrieve the right information at the right time.Overview

Knowledge sources tell the agent what it knows. When a user asks a question, the agent searches configured knowledge sources to find relevant information. It searches in real time — it doesn't memorize data, so it always works with the latest information available.

Configuration happens in the Build tab > Knowledge section, where you select which DevRev object types the agent can search.1. Available Knowledge SourcesAll Object Types

More knowledge sources ≠ better agent. Every additional object type:

Increases search surface area (more noise)

Increases retrieval time

Increases the chance of conflicting information

Makes the agent's reasoning trace harder to debugRule of Thumb

Start with the minimum set that covers the agent's stated goal. Add sources only when you observe a specific gap during testing.Decision Process1. Write the agent's goal
2. List the questions the agent must answer
3. For each question, identify the single best source
4. Add only those sources
5. Test
6. If the agent can't answer a question, add the specific missing source
7. Re-testExample: Customer Support AgentGoal: "Resolve customer issues by searching the knowledge base and performing account actions."

When the agent finds conflicting information across sources, it needs a resolution strategy. Encode this in the agent's instructions:When information conflicts across sources:
1. Prefer the most recently updated Article over Q&A entries
2. Prefer official policies over community answers
3. Prefer specific articles over general ones
4. If two articles from the same source conflict, prefer the one with the later "updated" date
5. If you cannot resolve the conflict, acknowledge it to the user and offer to escalate5.2 Source-Specific Instructions

You can write instructions that apply only when searching specific sources:When searching Articles:
- Focus on the "Rules" and "Summary" sections
- Ignore the "Internal Notes" section (marked with [INTERNAL])

When searching Tickets:
- Only consider tickets from the last 90 days
- Prefer resolved tickets over open ones for "how to" questions
- Look at the resolution summary, not the full conversation

When searching Account data:
- Always retrieve the full account profile including tier, health, and ARR
- Cross-reference with Rev Org for SLA entitlements5.3 Dynamic Knowledge Narrowing

For agents that serve multiple contexts, use instructions to dynamically narrow the knowledge scope:Context-dependent search rules:
- If the user is an external customer: search Articles (tagged 'external') and Q&A only
- If the user is an internal employee: search all enabled sources
- If the question mentions a specific product: add that product's Part hierarchy to the search
- If the question involves billing: search Articles tagged 'billing' first, then expand6. Knowledge Configuration ChecklistInitial Setup
